# Stage 07b — Backend Refactor: Session-Scoped Documents

Parent: [roadmap.md](roadmap.md) · Rules: [../../AGENTS.md](../../AGENTS.md) · SST: [../sdd.md](../sdd.md)

## Goal
Refactor the backend architecture to support strict **Session-Scoped Documents**. A document uploaded during a chat session belongs exclusively to that session. Retrieval queries strictly search only documents belonging to the active session. This bridges an architectural gap discovered during frontend design.

## Scope (In)
1. **Database Schema & Constraints**:
   - Add `session_id` (UUID, non-nullable) to the `documents` table as a Foreign Key to `chat_sessions.id`.
   - Configure `ondelete="CASCADE"` to ensure document rows are deleted when a session is deleted.
   - Update Deduplication Constraint: Change `UNIQUE(content_hash)` to `UNIQUE(content_hash, session_id)`. Duplicate files are rejected (409) *only* if uploaded to the same session.

2. **Route Evolution**:
   - **Remove**: `POST /api/v1/documents`, `POST /api/v1/documents/batch`, `GET /api/v1/documents`.
   - **Add**:
     - `POST /api/v1/chat/sessions/{session_id}/documents`
     - `POST /api/v1/chat/sessions/{session_id}/documents/batch`
     - `GET /api/v1/chat/sessions/{session_id}/documents`
   - **Keep**: `DELETE /api/v1/documents/{document_id}` (Global unique UUID).

3. **Validation & Pipeline Propagation**:
   - API endpoints must validate that the `session_id` exists before accepting uploads (404 if not found).
   - `DocumentService` handles saving `session_id` to the DB.
   - `IngestionService` reads `session_id` from the DB.
   - `QdrantVectorStore.upsert_chunks` injects `"session_id"` into the vector payload.

4. **Retrieval Filtering**:
   - `RetrievalService.retrieve` and `VectorStorePort.query` must require a `session_id` parameter.
   - `QdrantVectorStore.query` must strictly filter results using `Must(FieldCondition(key="session_id", match=MatchValue(value=str(session_id))))`.

5. **Session Deletion Semantics**:
   - `DELETE /api/v1/chat/sessions/{session_id}` must:
     1. Resolve all document IDs belonging to the session.
     2. Delete Qdrant points for all resolved documents.
     3. Delete physical files for all resolved documents.
     4. Delete the session row from the DB (triggering DB cascade for documents and messages).
   - *Error Handling*: Cross-system deletion is not transactional. If Qdrant deletion fails, bubble up a 502 (`VectorStoreDeletionError`). If filesystem deletion fails, bubble up a 500 (`StorageError`). Do not use ambiguous mapping; preserve idempotent retry semantics.

6. **Development Data Reset Utility**:
   - Because legacy development data lacks `session_id` payloads, it is considered disposable.
   - Create an explicitly invoked, development-only script (e.g., `scripts/reset_dev_data.py`) to wipe the local SQLite DB, delete local uploaded files in the directory configured via `Settings.UPLOAD_DIR` (not a hard-coded path), and reset the Qdrant collection.
   - Schema will be recreated via normal Alembic workflows. Due to SQLite's schema alteration limitations and the new non-nullable `session_id`, the autogenerated Alembic migration must be hand-reviewed and structurally validated for SQLite before applying. No legacy backfill is needed.
   - No auto-wipe on application startup.

## Out of Scope
- Virtual/shared documents across sessions.
- Modifying frontend code (Stage 08 remains paused).
- Advanced document management outside of scoped chat sessions.

## Impact on Prior Stages (01-07 Contracts)
- **API Breaking Changes**: Any external scripts/Postman collections relying on global document endpoints (`/api/v1/documents`) will break. They must migrate to the new `.../sessions/{session_id}/documents` endpoints.
- **Database Migrations**: Existing database schema will be altered. A new Alembic migration script will drop the global `content_hash` unique constraint, add the `session_id` column, set up the FK with cascade, and apply the new composite unique constraint.
- **Service Signatures**: `DocumentService.upload_document`, `DocumentService.upload_batch`, and `DocumentService.list_documents` will now require `session_id`. `RetrievalService.retrieve` will require `session_id`.
